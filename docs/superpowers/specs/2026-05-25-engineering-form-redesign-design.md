# Engineering Form Redesign Design

## Цель

Сайт должен за первые секунды объяснять, что «Инженерия формы» производит премиальную архитектурную мебель и интерьерные изделия по проектам архитекторов, дизайнеров и владельцев объектов. Основной сценарий: посетитель понимает уровень производства, видит типы задач, объекты, процесс и отправляет проект на оценку.

Редизайн должен сохранить ощущение дорогого бренда, но убрать абстрактность текущей версии. Новая страница должна продавать через ясность: что производим, для кого, из каких материалов, как ведем проект и как начать расчет.

## Визуальное направление

Утвержденное направление: **Editorial Production House**.

Стиль строится на спокойной премиальности: крупная editorial-типографика, темная графитовая база, реальные фотографии объектов и материалов, тонкие технические линии, подписи, координаты и асимметричная 12-колоночная композиция. Сайт должен ощущаться как цифровой каталог производственной культуры, а не как обычный каталог мебели.

## Палитра

Используем CSS-переменные:

- `--graphite-950: #070706`
- `--graphite-900: #11110F`
- `--stone-100: #F3EEE5`
- `--stone-300: #C9BDAA`
- `--walnut-500: #8A6242`
- `--brass-400: #C5A46D`
- `--lime-accent: #D7FF3F`

`--lime-accent` используется только для микро-акцентов: активные состояния, прогресс, технические метки. Основной интерфейс остается графитово-каменным с теплым walnut/brass слоем.

## Типографика

Сохраняем текущие шрифты:

- `Roundex` для display-заголовков;
- `Manrope` для основного текста, форм, навигации и технических подписей.

Не добавляем Inter, Roboto, Arial или system font как основной дизайн-выбор. Заголовки должны быть крупными, но текст в карточках, формах и FAQ остается читаемым на мобильных.

## Структура страницы

Страница остается одним лендингом, но данные готовятся так, чтобы позже можно было вынести SEO-страницы.

Порядок секций:

1. `HeroSection` — коммерческий H1, короткий scope, микро-доказательства, CTA на форму, CTA на объекты и CTA для отправки чертежей.
2. `AudienceSection` — архитекторы/дизайнеры, частные интерьеры, HoReCa, retail/коммерческие пространства.
3. `CapabilitiesSection` — производственные направления с короткими описаниями, материалами и ссылкой на форму.
4. `ProjectsSection` — фильтруемые кейсы с доступными кнопками фильтров и технической карточкой.
5. `MaterialsSection` — материалы, узлы, кромки, стыки, радиусы, ремонтопригодность и контроль оттенка.
6. `ProcessSection` — sticky timeline с этапами от брифа до сервиса после монтажа.
7. `TrustSection` — доказательные формулировки без выдуманных цифр.
8. `SeoTextSection` — компактный SEO-блок про мебель на заказ для архитектурных интерьеров в Москве.
9. `FaqSection` — 10 вопросов с короткими ответами и `FAQPage` JSON-LD.
10. `ContactSection` — проектный бриф с `mailto:` fallback и подготовкой к будущему API.

## Архитектура

Сохраняем стек React 19, TypeScript, Vite, Tailwind CSS, Framer Motion, Lenis и lucide-react. Новых зависимостей не добавляем без необходимости.

Целевая структура:

```txt
src/
  components/
    layout/
    sections/
    ui/
  data/
    siteContent.ts
    seo.ts
  hooks/
  lib/
  types/
```

Контент секций, FAQ, проекты, фильтры, аудитории, capabilities и контакты должны редактироваться из `src/data/siteContent.ts`. SEO-метаданные и JSON-LD храним в `src/data/seo.ts` или близком по смыслу модуле.

## Изображения

Основной материал берем из текущего репозитория:

- `public/projects/*`
- `public/gallery/*`
- `public/images/generated/materials/*`

Новые изображения можно генерировать только при явном визуальном пробеле. Нельзя выдавать сгенерированную сцену за реальный объект или реальный кейс. Для кейсов используем нейтральные описания без выдуманных клиентов, адресов, лет, наград или точных цифр.

## Motion

Motion должен поддерживать восприятие, а не мешать чтению.

Обязательные принципы:

- cinematic hero intro: линия/координаты, затем раскрытие изображения через `clip-path`, затем stagger заголовка;
- scroll reveal для секций через Framer Motion и CSS scroll-driven animation под `@supports`;
- parallax только на `transform` и `opacity`;
- hover на project cards, на mobile компактный overlay всегда видим;
- sticky process timeline со scroll progress;
- аккуратный reduced motion через варианты анимаций, а не глобальное принудительное ускорение до `0.01ms`.

## Форма

Контакты пока остаются заглушками:

- `atelier@engineering-form.example`
- `+7 (000) 000-00-00`

Форма становится проектным брифом с полями: имя, телефон или email, тип проекта, что нужно произвести, город/объект, желаемые сроки, наличие чертежей/визуализаций и комментарий.

Пока backend отсутствует, форма открывает почтовый клиент через `mailto:`. В интерфейсе нужно прямо указать, что откроется почтовый клиент. Код формы должен быть устроен так, чтобы позже заменить `mailto:` на API-отправку без переписывания всей секции.

## SEO и превью ссылок

`index.html` нужно обновить:

- title;
- meta description;
- `og:title`;
- `og:description`;
- `og:type`;
- `og:image`;
- `og:url`;
- `twitter:card`;
- canonical URL, если это не конфликтует с GitHub Pages.

Для превью ссылок используем существующее hero/project image с корректным путем для base path `/engineering-form/`.

JSON-LD:

- `Organization`;
- `LocalBusiness`;
- `Service`;
- `FAQPage`.

Не добавляем адрес, ИНН, юридические данные или реальные цифры, если их нет.

## Accessibility

Требования:

- видимый `focus-visible`;
- `aria-label` для навигации, меню, формы и кнопок без полного текстового контекста;
- фильтры проектов как кнопки с `aria-pressed`;
- декоративные motion-элементы с `aria-hidden="true"`;
- содержательные `alt` для контентных изображений;
- рабочая mobile navigation;
- нормальная клавиатурная навигация по фильтрам, ссылкам и форме;
- уважение `prefers-reduced-motion`.

## Мобильная оптимизация

Сайт должен быть отлично оптимизирован для мобильных устройств на iOS и Android. Мобильная версия не должна быть упрощенной копией desktop: hero, навигация, проекты, форма, FAQ и CTA должны сохранять ясную и премиальную подачу на узких экранах.

Требования:

- корректная работа в iOS Safari и Android Chrome;
- отсутствие горизонтального скролла на ширине от 320px;
- удобные touch targets не меньше 44px по высоте или ширине для интерактивных элементов;
- читаемые размеры текста без масштабирования viewport и без обрезанных длинных слов;
- mobile navigation с понятным состоянием открытия, закрытия и фокуса;
- формы с подходящими `inputMode`, `autoComplete`, видимыми ошибками и удобной клавиатурой на телефоне;
- изображения с заданными пропорциями, чтобы не было скачков layout при загрузке;
- motion на мобильных должен быть легче, чем на desktop, без агрессивного parallax и без рывков при скролле;
- корректная работа safe area на iPhone, включая устройства с notch.

## Performance

Требования:

- не добавлять тяжелые зависимости;
- hero image грузить приоритетно;
- остальные изображения: `loading="lazy"`, `decoding="async"`;
- задавать aspect ratio, чтобы избежать CLS;
- анимировать в основном `transform` и `opacity`;
- проверить `npm run lint` и `npm run build`.

## Проверка

Перед завершением реализации нужно проверить:

- desktop около 1440px;
- tablet;
- mobile около 390px;
- узкий mobile около 320px;
- iOS Safari и Android Chrome, если доступны для ручной проверки;
- якорную навигацию;
- отправку формы через `mailto:`;
- reduced motion;
- отсутствие горизонтального скролла;
- читаемость на темном фоне;
- корректность base path `/engineering-form/`;
- превью ссылок через Open Graph/Twitter tags.
